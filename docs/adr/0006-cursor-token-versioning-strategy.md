# ADR-0006: Cursor Token Versioning Strategy

## Status

Accepted

## Date

2026-08-09

## Author

Audit-Driven Engineering Review

---

## Context

EricksonLopez.Pagination encodes pagination state as opaque cursor tokens. These tokens are:

- Stored in browser history, bookmarks, and frontend state
- Transmitted via API query parameters (`?after=...`)
- Generated and validated by the server-side `KeysetBuilder<T>`

When the keyset schema changes (e.g., adding or removing a sort column), existing cursor tokens may become invalid or — worse — silently misinterpreted by a different keyset configuration.

### Cursor Format History

| Version | Format | Fingerprint | Status |
|---------|--------|-------------|--------|
| v1 | `M\|col1\|col2` | No | **Deprecated** |
| v2 | `M\|v2\|{fingerprint}\|col1\|col2` | Yes (hash of column types + order) | **Current** |

---

## Problem

1. **Cross-keyset confusion (v1)**: A v1 cursor has no fingerprint. A cursor generated for a 2-column keyset could be accepted by a 1-column keyset if both have the same number of pipe-delimited parts, leading to incorrect SQL predicates without any exception.

2. **Schema migration breakage**: When a developer changes the keyset columns, all existing v2 cursors are invalidated because the fingerprint no longer matches. Active users in the middle of pagination will receive `InvalidPaginationCursorException`.

---

## Decision

### D1: v2 is the canonical format
All new cursors generated by `KeysetBuilder.EncodeCursor` use the `M|v2|fingerprint|...` format.

### D2: `AcceptLegacyCursors` option controls v1 acceptance
`PaginationCoreOptions.AcceptLegacyCursors` (default: `true`) allows backward-compatible migration.

**Migration path**:
1. Deploy with `AcceptLegacyCursors = true` (default)
2. After cursor TTL has elapsed (1-7 days), set `AcceptLegacyCursors = false`
3. Old v1 cursors receive `InvalidPaginationCursorException` -> redirect to page 1

### D3: No automatic cursor migration between keyset versions
Cursor tokens from one keyset schema cannot be safely translated to another. Frontend clients must handle HTTP 400 by resetting pagination.

### D4: Prefer HmacCursorEncoder with TTL in production
`HmacCursorEncoder` with `TimeToLive` bounds cursor validity, automatically expiring stale cursors during schema migrations.

---

## Consequences

- Clear migration path from v1 to v2
- Fingerprint validation prevents cross-keyset misuse  
- `AcceptLegacyCursors = false` hardens production deployments
- No automatic cursor translation means user sessions reset on schema change
